# PlayDock · 玩坞

**让 AI 生成的游戏，从原型走向玩家。**

[English](README.md) · [架构设计](docs/architecture.md) · [4 周交付计划](docs/roadmap.md) · [上传清单示例](examples/game.manifest.json)

## 我们要解决什么

AI 一句话生成游戏已经很常见，但生成之后，创作者仍然缺少测试、托管、发布、获取玩家和变现的一整套流程。PlayDock 计划把这些环节连接起来：创作者可以上传 AI 辅助制作的游戏，选择私有试玩、公开分享，或在后续商业化阶段出售访问权限。

平台的核心是“提交 → 隔离构建 → 自动试玩 → 审核 → 发布 → 持续监控”。技术检查负责发现运行问题，人工试玩与玩家反馈负责补足可玩性判断。

## 当前进度

**目前处于规划阶段，尚无可运行的平台。** 本仓库提供项目框架、架构和验收计划；沙盒、支付与各项指标均未实现或验证。4 周计划从正式开发启动时计算。

计划使用 **Devin Bots** 承担明确范围的开发任务，通过验收条件和人工代码审查交付。这是独立项目，不代表已获得 Cognition 的赞助、额度或官方合作。

## 第一版做什么

- 先支持构建为静态资源的 HTML5 / JavaScript / WebGL 轻游戏。
- 支持上传来自不同 AI 工具的项目，平台内“一句话生成游戏”留到后续。
- 提供创作者后台、版本管理、审核报告和私有 / 公开发布。
- 提供游戏目录、评价、举报和带最低样本门槛的排行榜。
- 用支付测试模式验证付费访问、购买凭证和创作者收入台账；真实收款与提现单独验收。

## 如何避免上架即报错

1. **上传规范：** 代码包和 manifest 声明入口、构建方式、权限、资源与素材来源；先检查压缩包路径、大小和格式。
2. **源码检查：** 检测泄露密钥、已知漏洞依赖、可疑脚本和越权能力，输出可追踪的问题报告。
3. **隔离构建：** 在独立、可销毁的执行环境里构建，限制 CPU、内存、时长和网络；普通 Docker 容器本身不作为充分的恶意代码隔离方案。
4. **自动试玩：** 运行已有单测，以及“加载—开局—互动 3 分钟—重新开始”的浏览器流程，记录截图、异常和网络行为。Devin 辅助编写测试，平台保留独立检查。
5. **人工复核：** 首批公开游戏逐个试玩，检查玩法循环、内容与素材声明；付费、推荐游戏增加复核。通过构建不等于好玩，也不等于版权已被证明。
6. **按版本发布：** 审核结果绑定产物摘要，更新代码后必须重新审核，不能用旧审批替换新代码。
7. **上线监控：** 根据加载错误、异常和举报暂停问题版本，必要时恢复之前已审核的版本。

私有游戏也需要基础安全检查；公开发布再增加内容和可玩性审核。

## 4 周交付目标

| 周次 | 交付内容 | 验收方式 |
| --- | --- | --- |
| 第 1 周 | 上传规范、版本模型、威胁模型、隔离构建原型 | 示例游戏生成版本化产物；非法压缩包和超限任务被拒绝 |
| 第 2 周 | 自动审核 runner、浏览器试玩、审核报告 | 正常游戏通过；入口错误、运行崩溃和违规联网的样本被拦截 |
| 第 3 周 | 创作者后台、私有 / 共享发布、测试支付 | 验证私有访问权限；重复支付回调不会重复发放权益 |
| 第 4 周 | 游戏目录、排行榜、监控、10 个种子游戏 | 发布试玩记录、故障回滚演示和已知限制说明 |

## 变现假设

先验证付费游戏交易抽成：暂定平台 20%、创作者 80%，手续费、税费与退款的具体口径在真实交易上线前明确。后续验证创作者 Pro：提供更多存储、私有项目配额和数据分析，不出售审核豁免或自然榜单名次。

生成额度包、玩家订阅、企业私有部署都属于后续探索，不塞进首版。

## 需要验证的指标

- 4 周内完成 10 个有构建和审核记录的种子游戏。
- 小型基准游戏自动审核阶段目标少于 10 分钟；排队和人工审核时间单独计算。
- 可观测会话中的加载失败或未捕获异常比例目标低于 1%，同时公布样本量和监控盲区。
- 正式公开运营首月尝试达到 20 个过审游戏；真实支付开放后，验证至少 3 款游戏产生购买。

这些数字是目标，不是当前成绩或服务承诺。完整技术细节和任务拆解见 [架构](docs/architecture.md) 与 [路线图](docs/roadmap.md)。欢迎通过 GitHub Issues 提供种子游戏或参与实现。
